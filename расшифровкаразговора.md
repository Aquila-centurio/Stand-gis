На основе транскрипции совещания можно выделить следующие требования (в основном к проведению аудита защищённости и оформлению отчёта):

1. **Сканирование уязвимостей**  
   - Использовать сканеры уязвимостей (Nessus, OpenVAS, Languard, сканер WS, Acunetix, ZAP и др.).  
   - Сортировать уязвимости по убыванию значимости; концентрироваться на красно-оранжевых (критических и высоких).  
   - Для каждой уязвимости изучать описание, ссылку на исправление и оценку опасности.  
   - При эксплуатации уязвимостей (например, через Metasploit) соблюдать осторожность, чтобы не нарушить работу критических сервисов.

2. **Проверка веб-приложений**  
   - Проверять веб-приложения на уязвимости, использовать базы данных уязвимостей, применять знания на лабораторных работах.

3. **Аудит операционных систем**  
   - **Windows**: проверять локальную политику безопасности.  
   - **Linux**: анализировать файлы `/etc/passwd` (пользователи с UID 0), `/etc/shadow` (политики паролей: максимальный и минимальный срок), группу `sudo`, PAM-модули.  
   - **Astra Linux**: использовать графический инструмент управления политиками безопасности.

4. **Аудит доменов**  
   - Для Active Directory использовать утилиту Pink Castle (скачать с GitHub), запускать с учётной записью администратора домена, анализировать индикаторы опасности (красные стрелки).  
   - Для FreeIPA и Astra доменов проводить проверку вручную (инструментов нет).

5. **Локальные проверки систем**  
   - Использовать скрипты PEASS (PIES) с GitHub для Linux и Windows, запускать и анализировать результаты (время выполнения ~5 минут).

6. **Проверка разграничения доступа**  
   - Анализировать дискреционное и мандатное разграничение доступа: матрицу прав (чтение, запись, исполнение).  
   - При наличии СЗИ использовать её матрицу доступа.  
   - Учитывать отдельные документы по отделам, если они есть.

7. **Проверка средств защиты информации (СЗИ)**  
   - СЗИ (SecretNet, Dallas Lock и др.) должна быть настроена, иметь лицензию, включённый контроль целостности, желательно замкнутую программную среду.  
   - Обязателен контроль подключения внешних устройств (защита от утечки через флешки).  
   - Антивирус должен обновляться, проводиться полная проверка, наличие лицензии.

8. **Журналирование событий**  
   - Обязательно вести журналирование событий безопасности.  
   - Предпочтительно использовать удалённые журналы (сложнее почистить).

9. **Проверка систем обнаружения вторжений (СОВ)**  
   - Проверять механизмы обновления СОВ, тестовые сработки, запись сообщений о сработках, корреляцию и оповещение пользователей.

10. **Оформление отчёта**  
    - Включать конкретные проблемы, найденные сканером и вручную.  
    - Обязательно выдавать рекомендации по устранению недостатков.  
    - Прикладывать отчёты сканеров.  
    - Не преувеличивать опасность, чтобы избежать необоснованных требований.  
    - Отчёт должен позволять обосновать выборы мер защиты.
