мы планируем развернуть стенд ГИС в docker, в стенде должно быть:

- 2 МЭ, которые образуют ДМЗ
- До МЭ1 внешняя сеть
- На всех МЭ предлагается использовать nftables в качестве firewall
- На серверах предалагается использовать alpine, для уменьшения веса, если нет готового контейнера и это не помешает работе сервисов
- Если проблемы с alpine возникают, то использовать debian
- Для АРМ необходимо использовать Debian с графикой, чтобы к клиенту можно было подключиться по VNC
- все необходимо развернуть через один docker compose, для удобного поиска переменных, подсетей и так далее
Разворачиваемые серверы:

	- [ ] МЭ1
	- [ ] МЭ2
	- [ ] RADIUS (freeradius/freeradius-server)
	- [ ] VPN(openvpn/openvpn-as)  wg-portal?
	- [ ] FreeIPA (freeipa/freeipa-server)
	- [ ] nginx(reverse proxy для зеркалирования трафика на suricata)
	- [ ] EML (mailcow)
	- [ ] Suricata
	- [ ] БД (postgres)
	- [ ] FTP (bogem/ftp)
	- [ ] DNS
	
Есть нюансы реализации:

1) Адресация в подсетях статическая
2) Рекомендуется использовать не требовательные к вычислительным ресурсам узлы
3) Допускается объединение нескольких сервисов на одном узле в ДМЗ
4) Технологии, используемые на узлах выбираются в подгруппах самостоятельно. Подгруппа состоит из Зх человек,
разумно запускать каждый сегмент сети на отдельном компьютере участника группы
5) В частной подсети можно использовать только 1 АРМ в целях экономии вычислительных ресурсов
6) В рамках ЛР «Проектирование ГИС» допускается не настраивать контроль доступа (ACL и/или инспектирование
трафика) на FW. Это позволит провести внешний аудит узлов всех подсетей без переключения сканеров
безопасности.
7) Пользователи частной подсети для доступа в интернет должны пройти авторизацию Ha RADIUS
8) Логи узлов должны быть настроены на протоколирование событий. Хотя бы минимально.
